# 需求度量体系

为持续优化建立度量口径。命令入口见 `/crs:metrics`（选项与输出示例不在此重复）；本 skill 定义**度量什么、怎么算、怎么用**。

## 四维度指标口径

**效率**
| 指标 | 计算方式 | 目标 |
| --- | --- | --- |
| 需求交付周期 | completed_at − created_at | ↓ 50% |
| 平均创建时间 | brainstorm 分析耗时 | <10分钟 |
| 平均实现时间 | 计划到完成的实际开发时间 | ↓ 30% |
| 流程效率 | 有效时间 / 总时间 | >80% |

**质量**
| 指标 | 计算方式 | 目标 |
| --- | --- | --- |
| 返工率 | 返工需求数 / 总需求数 | <15% |
| 门禁通过率 | 首次通过数 / 总检查数 | >90% |
| Bug密度 | Bug数 / 功能点数 | <0.5 |
| 验证通过率 | 通过项 / 总检查项 | >95% |

**变更**
| 指标 | 计算方式 | 目标 |
| --- | --- | --- |
| 变更频率 | 变更次数 / 需求数 | ↓ 40% |
| 重大变更占比 | 重大变更数 / 总变更数 | <20% |
| 变更响应时间 | 变更处理耗时 | <2小时 |
| 影响评估准确率 | 准确评估数 / 总评估数 | >85% |

**价值**
| 指标 | 计算方式 | 目标 |
| --- | --- | --- |
| 需求完成率 | 按时完成数 / 总需求数 | >90% |
| 优先级准确率 | 准确评估数 / 总评估数 | >80% |
| ROI达成率 | 实际ROI / 预期ROI | >100% |
| 用户满意度 | 满意度评分 | >4.0/5.0 |

## 数据收集

自动收集三个时机：需求创建（类型/模式/耗时）、门禁检查（gate/是否通过/评分）、需求完成（周期/返工次数/变更次数）。数据落 `.requirements/metrics/data.yaml`（每指标一条 {date, value, ...} 记录）；手动里程碑记录可追加到同目录。

## 分析方法

- **趋势**：对时间序列计算趋势线（up/down/stable）+ 下一期预测 + 异常检测，异常时给建议
- **对比**：与历史均值比（好 10%+/差 10%+/持平），与目标比（达成率 = 当前/目标，报差距）
- **告警**：指标超 `alerts.thresholds`（warning/critical 两级）时在报告中输出当前值/阈值/超出幅度/建议

## 持续改进（PDCA）

Plan：从度量报告识别问题、定改进目标 → Do：实施并收集数据 → Check：对比改进前后指标 → Act：有效措施标准化，无效继续优化。

## 集成

- 数据来源：`meta.yaml`（时间/状态）、`req-quality`（门禁结果）、`req-change`（变更记录，级别标记取自 CHANGELOG 小节标题）
- 触发：需求创建 / 门禁检查 / 需求完成时自动采集；报告每周或每月生成
- 输出：data.yaml（数据）、Markdown 报告、告警通知
