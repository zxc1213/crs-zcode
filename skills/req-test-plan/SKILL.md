# 测试计划生成器

基于设计文档（`spec/design.md` 等）生成可执行的测试覆盖，阶段 4 由 `/crs:req` 自动调用。

## 生成规则（从设计提取测试场景）

1. **功能描述 → 功能测试**：每个功能点至少 3 条（正常、边界、异常）
2. **API 定义 → API 测试**：每个接口至少 5 条（正常、参数缺失、类型错误、超长、特殊字符）
3. **数据约束 → 边界测试**：边界外/边界内/边界值各取（如"长度 3-20" → 2/3/20/21）
4. **错误处理 → 异常测试**：逐个失败分支生成（如"重试3次" → 1/2/3/4 次各一条）
5. 有 UI 设计补交互与可访问性；有性能要求补响应时间/吞吐/并发基准；有安全面补注入/XSS/权限

按测试类型选覆盖面：功能 / API / UI / 性能 / 安全，至少覆盖 3 种。

## 用例优先级

| 优先级 | 条件 | 说明 |
| ------ | ---- | ---- |
| P0 | 核心功能、主要业务流程 | 必须测试，失败阻塞发布 |
| P1 | 重要功能、常用场景 | 必须测试，失败需评估 |
| P2 | 边缘功能、异常场景 | 尽量测试，失败可延后 |
| P3 | 辅助功能、优化项 | 可选测试 |

## 执行步骤

1. **读设计**：提取功能列表、接口定义、数据流、错误处理、性能与安全要求
2. **定类型**：按设计内容选择测试类型组合
3. **生成用例**：按上方生成规则产出；每条用例含 ID/场景/前置条件/步骤/预期结果/优先级
4. **落盘**：写入 `test-cases/positive.md`（正向）、`negative.md`（异常）、`boundary.md`（边界）三个文件（表格式见骨架），并更新 `test-cases.md` 的测试范围表与索引状态

用例 ID 惯例：`TC-<类型缩写>-NN`（如 TC-POS-01 / TC-NEG-02 / TC-BND-03）。

## NEVER 清单

- **绝不**跳过核心功能用例 / 忽略边界条件 / 省略错误处理测试
- **绝不**遗漏性能与安全面（设计中有要求时）
- **绝不**生成无法执行的用例（步骤不可操作、预期不可判定）

## 输出与协作

- 输出文件：`test-cases.md`（索引）+ `test-cases/{positive,negative,boundary}.md`
- 时序：设计文档完成后、`writing-plans`（阶段 5）之前
- 相关：`req-brainstorm`（设计输入）、`writing-plans`（计划参考测试）、`test-driven-development`（TDD 时结合）

生成后交用户审查，按反馈调整；实现阶段按用例验收。
